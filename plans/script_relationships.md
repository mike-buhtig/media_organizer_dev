Scripts and Their Roles
1. ### Season_Episode_builder.py

Purpose: Fetch TV series metadata from providers and generate a consolidated JSON file.
Inputs:
--series: Series name (e.g., Ax Men).
config/paths.txt: Configuration with [meta_providers] and [series] sections.


Outputs:
data/<series_slug>/<series_name>.json (e.g., data/ax_men/Ax Men.json) with raw provider data, preserving [meta_providers] order.
tmp/<name>.json (e.g., tmp/tvmaze.json) per enabled provider, deleted before writing.
logs/<series_slug>/builder.log (e.g., logs/ax_men/builder.log).


Dependencies:
Calls <name>.py modules dynamically based on the authoritative [meta_providers] top-to-bottom priority order: TMDb first, Trakt second, TVMaze third, Rotten Tomatoes fourth, and Rotten Tomatoes 2 fifth.
Reads tmp/<name>.json files generated by providers.



2. ### series_folder_crawler.py

Purpose: Crawl series folders to match files with metadata, normalizing names for comparison.
Inputs:
Series JSON: data/<series_slug>/<series_name>.json from Season_Episode_builder.py.
Configuration: paths.txt with [series] (e.g., series_path_1).


Outputs:
Potentially extended JSON or internal data structures for matching files to episodes.


Behavior:

- Scans a designated series folder for recorded media files (.ts) and their associated NextPVR EPG metadata (.xml) files.
- Employs a multi-pass matching strategy to correlate local EPG data with comprehensive provider metadata generated by Season_Episode_builder.py, intelligently handling variations in titles (e.g., "and" vs. "&").
- Correctly identifies and includes the file size of the local `.ts` recordings in the output.
- Produces a structured JSON file (`<series_slug>_Processed.json`) that meticulously maps local recordings to their corresponding episode metadata from various providers. This detailed output is essential for subsequent renaming, NFO file creation, and organization by `file_organizer.py`.
- Includes an "unmatched" season in the output for local recordings that could not be associated with provider metadata.


Dependencies:
- Consumes JSON from Season_Episode_builder.py.
- `config/paths.txt`: Contains configuration settings, including the root folder for series recordings, the location of the metadata JSON, output paths, and matching thresholds specific to each series.  The thresholds set sensitivity of fuzzy logic in matching episodes that fail to match in pass 1


3. ### file_organizer.py

Purpose: Organize media files into a structured directory based on metadata.
Inputs:
Series JSON: data/<series_slug>/<series_name>.json.
Configuration: paths.txt with [series] (e.g., series_path_1), OPERATION_MODE, CREATE_NFO.


Outputs:
Source recordings: the exact series_path_X configured for the series.

Organized files: TV_LIBRARY_PATH/<series_name>/Season <N>/<series_name> - S<NN>E<NN>_<episode_name>.ext, using episode names from highest-priority provider.

Persistent organizer metadata: TV_LIBRARY_PATH/<series_name>/.media_organizer/.
Optional .nfo files.


Dependencies:
Consumes JSON from Season_Episode_builder.py, potentially via series_folder_crawler.py.
Uses [series] section for series paths.



4. kodi_db_exporter.py

Purpose: Export metadata to Kodi’s database.
Inputs:
Series JSON: data/<series_slug>/<series_name>.json.
Configuration: paths.txt with USE_KODI.


Outputs:
Database entries in Kodi’s MySQL or SQLite database.


Dependencies:
Consumes JSON from Season_Episode_builder.py.



5. Provider Modules

Location: scripts/providers/
Naming: <name>.py (e.g., tvmaze.py), with unique names for each provider.
Purpose: Fetch metadata for a series and write to tmp/<name>.json with raw data.
Inputs:
series_name: Series name (e.g., Ax Men).
config: ConfigParser object with paths.txt settings (e.g., API_KEY, SCRAPE_DELAY).


Outputs:
tmp/<name>.json (e.g., tmp/tvmaze.json).


Called By: Season_Episode_builder.py dynamically based on [meta_providers] priority order.

Configuration

config/paths.txt: Defines providers (tvmaze=enabled), series (series_name_1 = The A-Team), paths (JSON_FOLDER, TEMP_FOLDER, LOG_PATH), and settings (USE_KODI, OPERATION_MODE, SCRAPE_DELAY).
config/paths.example.txt: Template for paths.txt with placeholder settings.

References

plans/requirements.md: Functional requirements, configuration structure, and JSON output format for Season_Episode_builder.py.
plans/coding_conventions.md: Coding practices and provider conventions.
config/paths.example.txt: Configuration template.

Provider Precedence

Providers are listed in config/paths.txt under [meta_providers] in authoritative top-to-bottom order: tmdb, trakt, tvmaze, rotten_tomatoes, rotten_tomatoes2.
The order defines their precedence for downstream processes (e.g., crawler, file organizer): TMDb first, Trakt second, TVMaze third, Rotten Tomatoes fourth, and Rotten Tomatoes 2 fifth.
All providers’ metadata is included in data/<series_slug>/<series_name>.json for each field (titles, overviews, ids, air_date), with no data discarded during merging.
The order of provider keys in data/<series_slug>/<series_name>.json (e.g., titles: { "tmdb": "...", "trakt": "...", "tvmaze": "..." }) matches the order in [meta_providers] to ensure downstream scripts recognize the priority of providers.

Logging (Season_Episode_builder.py)

Script actions: logs/<series_slug>/<series_slug>_builder.log (e.g., logs/ax_men/ax_men_builder.log).
Provider actions: logs/<series_slug>/<series_slug>_provider.log (e.g., logs/ax_men/ax_men_provider.log).
Both logs reside in logs/<series_slug>/ and are written in append mode.
Providers log through Season_Episode_builder.py’s logging mechanism.
These requirements apply only to Season_Episode_builder.py and its provider scripts (tvmaze.py, tmdb.py, trakt.py, rotten_tomatoes.py).
Note: Logging for downstream scripts (file_organizer.py, series_folder_crawler.py, kodi_db_exporter.py) will be defined in future updates. This note will be removed when those directives are complete.
